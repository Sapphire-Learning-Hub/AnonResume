<h2 id="start-editing">进入 Markdown 编辑</h2>

打开简历后，在“开始”中选择“Markdown 编辑”。左侧是源码，右侧是只读预览。你可以滚动、缩放和查看预览，但不能直接修改右侧画布；此时所有内容修改都通过左侧完成。

段落、三级标题、粗体、斜体、删除线、行内代码、链接、有序列表和无序列表使用常见 Markdown 写法。

```markdown
### 高级后端工程师

负责 **核心服务** 与 *工程效率* 建设。

- 交付用户认证功能
- 改善可观测性与故障恢复
```

<h2 id="page-theme">设置页面与主题</h2>

设置区是可选的。进入 Markdown 编辑时，编辑器会生成包含当前页面与主题设置的设置区；手动编写一份没有设置区的 Markdown 时，会继续使用当前简历的设置。`anonresume: 1` 表示设置区的语法版本。页边距的四个数字依次为上、右、下、左。

```markdown
---
anonresume: 1
title: "后端工程师简历"
locale: zh-CN
page-margin: 18 16 18 16
font-family: "Noto Sans SC"
font-size: 10.5
line-height: 1.55
accent: "#1677ff"
text-color: "#111827"
muted-color: "#64748b"
---
```

字体名称需要来自当前实例可用的简历字体。颜色使用十六进制值。你可以删除不需要显式修改的设置项，也可以删除整个设置区。

<h2 id="content-structure">编写章节、布局与富文本</h2>

二级标题表示简历章节。大多数简历内容直接使用标准 Markdown 即可。

```markdown
## 工作经历

### 高级工程师

负责核心服务与工程效率建设。

- 交付用户认证功能
- 改善可观测性与故障恢复
```

只有标准 Markdown 无法表达的布局才需要块指令。指令以 `:::名称` 开始，以单独一行的 `:::` 结束。横向布局可以在一个 `row` 中使用三级标题划分各列：

```markdown
:::row {gap=16 align="center" justify="between"}
### 高级工程师

示例公司

### 任职时间

2024.01 - 至今
:::
```

当内容没有稳定标题边界，或确实需要水平分组时，可以使用最少量的 `group` 指令。普通标签在本机编辑会话中可以继续写成标准无序列表；如果希望单独复制源码后仍明确识别为标签集合，可以使用 `badges`：

```markdown
:::badges {wrap=true gap=8}
- TypeScript
- PostgreSQL
:::
```

链接、粗体、斜体、删除线和行内代码使用标准 Markdown。图标以及需要显式写入源码的少量扩展样式可以使用行内指令：

```markdown
:tag[核心技能]
:icon[simple-icons:github]
:color[:underline[重点内容]]{value="#1677ff"}
[联系我](mailto:hello@example.com "发送邮件"){color="inherit" underline=false}
```

需要在同一段内换行时，在行尾保留两个空格后再换行。普通空行用于分隔段落。

<h2 id="diagnostics">处理问题与规范化</h2>

源码有问题时，左侧会显示行号和说明。选择一条问题可以定位到对应位置。如果问题会阻止解析，右侧会继续显示上一个有效预览，且这些错误修改不会被保存到简历。

离开 Markdown 编辑时，编辑器只会统一换行符、移除多余的连续空行，并补齐文件末尾换行。注释、列表符号、强调写法和围栏代码内容会保留。如果当前源码仍有阻断错误，你可以继续修改，或明确放弃错误修改。

部分仅存在于可视化编辑器中的布局或样式不会反复写入 Markdown。它们会随当前本机编辑会话一同保留；如果某一处内容变化后无法继续准确对应，问题列表会提示该处已使用默认设置重建，其他内容不受影响。

浏览器异常刷新后，如果检测到本机未完成的 Markdown 源码，页面会让你选择恢复或从当前简历重新开始。

<h2 id="compatibility">兼容性与可移植范围</h2>

编辑器可识别普通 Markdown，也兼容已支持的旧版 AnonResume 块指令，以及木及简历 `:::left`、`:::right` 和 `icon:名称` 写法。新内容建议优先使用标准 Markdown，只在布局确实需要时使用 `row`、`group` 或 `badges`。

单独复制 Markdown 源码可以携带可见内容、显式块指令和设置区中的公开设置，但不会携带仅在当前本机保留的设计细节。因此，Markdown 源码适合编辑和迁移公开语义，不是完整备份，也不应代替平台的正常保存与导出流程。需要跨设备稳定保留某个特殊布局时，请把对应的稀疏块指令保留在源码中。

Markdown 注释可以保留。其他原始 HTML、脚本和自定义 CSS 不受支持。
