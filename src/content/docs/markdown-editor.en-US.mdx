<h2 id="start-editing">Enter Markdown editing</h2>

Open a resume and choose **Markdown editing** in the left sidebar. The source is on the left and a read-only preview is on the right. You can scroll, zoom, and inspect the preview, but you cannot edit the right-hand canvas directly. All content changes come from the source while this mode is active.

Paragraphs, level-three headings, bold, italic, strike-through, inline code, links, ordered lists, and unordered lists use familiar Markdown syntax.

```markdown
### Senior backend engineer

Built **core services** and improved _engineering efficiency_.

- Delivered user authentication
- Improved observability and recovery
```

<h2 id="page-theme">Set up the page and theme</h2>

The settings block is optional. When you enter Markdown editing, the editor generates one from the current page and theme settings. If you write Markdown without this block, the resume keeps its current settings. `anonresume: 2` identifies the current syntax version; existing `anonresume: 1` source remains readable. The four page-margin numbers are top, right, bottom, and left.

```markdown
---
anonresume: 2
title: "Backend engineer resume"
locale: en-US
page-margin: 18 16 18 16
font-family: "IBM Plex Sans"
font-size: 10.5
line-height: 1.55
accent: "#1677ff"
text-color: "#111827"
muted-color: "#64748b"
---
```

The font name must be available in the resume font collection for the current instance. Colors use hexadecimal values. You can remove settings that do not need an explicit override, or remove the whole settings block.

<h2 id="content-structure">Write sections, layouts, and rich text</h2>

A level-two heading starts a resume section. Most resume content can use standard Markdown directly.

```markdown
## Experience

### Senior engineer

Built core services and improved engineering efficiency.

- Delivered user authentication
- Improved observability and recovery
```

Use block directives only for structures that standard Markdown cannot express. A directive starts with `:::name` and ends with `:::` on its own line. Use `row` for horizontal layout and `group` to retain each compound column's boundary, with ordinary Markdown inside:

```markdown
:::row {gap=16 align="center" justify="between"}
:::group

### Senior engineer

Example Company
:::

:::group

### Dates

2024.01 - Present
:::
:::
```

For an image on the right, use `:::row {columns="image-right" gap=16 align="start"}`. Place the left-column content first and one image second. Wrap multiple left-column blocks in one `group`. The right column reserves the image's configured width, while text continues on later pages at the same left-column width without repeating the image. Copy image Markdown from **My images**.

Use `layout` for a section's equal-width columns. Keep one `group` boundary around a column containing several blocks. Use `column` when a single text block with multiple paragraphs forms a column, and write ordinary paragraphs inside. Ordinary vertical groups inside a column do not need repeated wrappers:

```markdown
## Experience

:::layout {columns=2 gap=22}
:::group

### Community Manager

2024 — Present

Created member events and editorial programs.
:::

:::group

### Marketing Associate

2022 — 2024

Supported live events and post-program reviews.
:::
:::
```

Badge collections and bullet lists have different meanings. An independent paragraph consisting entirely of backtick items represents badges, without an extra directive:

```markdown
`TypeScript` `PostgreSQL`
```

A single standalone backtick item also represents a badge. Backticks mixed into prose remain inline code. Use fenced code for standalone code. Backticks in version-one source retain their previous inline-code meaning.

Ordinary multi-paragraph text uses paragraphs and blank lines directly. Use `:::text` only when empty paragraphs must be preserved or a code-only paragraph must be distinguished from badges. Lists containing compound content such as tags or layouts use `:::list` and `:::item`; ordinary lists and nested lists keep standard syntax. Adjacent independent lists may be separated by an `<!-- anonresume:block -->` comment to prevent them from merging. Keep that comment in place.

Links, bold, italic, strike-through, and inline code use standard Markdown. Icons and the few styles that must be explicit in source can use inline extensions:

```markdown
:tag[Core skill]
:icon[simple-icons:github]
:color[:underline[Important text]]{value="#1677ff"}
[Contact me](mailto:hello@example.com "Send email"){color="inherit" underline=false}
```

For a line break within one paragraph, leave two spaces at the end of the line before pressing Enter. A normal blank line separates paragraphs.

<h2 id="diagnostics">Resolve issues and normalization</h2>

When the source has a problem, the left pane shows its line number and an explanation. Select an issue to move to that location. If an issue prevents parsing, the right pane keeps showing the last valid preview and the invalid changes are not saved to the resume.

When you leave Markdown editing, the editor only normalizes line endings, removes redundant blank lines between blocks, and adds the final newline. Empty paragraphs inside `text`, comments, list markers, emphasis spelling, and fenced code contents remain intact. If the current source still has a blocking error, you can continue editing or explicitly discard the invalid changes.

Some layout and styling details exist only in the visual editor instead of being repeated in Markdown. They remain available during the current local editing session. If edited content can no longer be matched reliably, changes are paused and the last valid preview and local source are retained, rather than automatically rebuilding the resume. Try splitting a large change into smaller edits.

After an unexpected browser refresh, the page may find unfinished Markdown source saved on this device. You can choose to recover it or restart from the current resume. Source whose original baseline cannot be verified remains available for inspection, but cannot overwrite the current resume.

<h2 id="compatibility">Compatibility and portability</h2>

The editor recognizes ordinary Markdown, supported legacy AnonResume directives (including `badges`), and the Mujicv `:::left`, `:::right`, and `icon:name` forms. Prefer standard Markdown for new content and use `layout`, `row`, `group`, or `column` only when the layout requires them.

Copying the Markdown source carries visible content, explicit block directives, and public settings from the settings block. It does not carry design details retained only on the current device. Markdown source is therefore useful for editing and moving public semantics, but it is not a complete backup and should not replace the platform's normal save and export flows. Keep the relevant sparse directive in source when a special layout must survive across devices.

Markdown comments are preserved. Other raw HTML, scripts, and custom CSS are not supported.

Images use `![alternative text](anonresume-asset:image-id)`. Choose **Copy Markdown** from an image's menu in **My images** to obtain a valid reference. Optional title parameters preserve size and cropping when needed. External image URLs are not supported. The source references an asset in your account, not the image file itself; copying the source does not share the asset with another account.
