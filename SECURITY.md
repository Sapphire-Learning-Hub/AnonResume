# Security Policy

## Supported versions

Security fixes are prepared for the latest stable release. A current prerelease may also receive a fix when the issue affects upcoming code. Older releases may need to upgrade before a fix can be applied.

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/Sapphire-Learning-Hub/AnonResume/security/advisories/new) whenever possible. Do not disclose vulnerability details in a public issue, discussion, support form, or chat.

Include:

- The affected version or commit.
- The security impact and who could be affected.
- Clear reproduction conditions and the smallest evidence needed to confirm the issue.
- Any prerequisite configuration or user action.
- Suggested mitigations, if known.

Do not include passwords, tokens, private keys, personal resumes, or other real user data.

## Research boundaries

Good-faith research must avoid accessing, downloading, changing, or deleting data that belongs to other users. Do not disrupt a production service, bypass rate limits at scale, maintain persistence, or publish an exploit before maintainers have had a reasonable opportunity to investigate and coordinate a fix.

If testing could affect a real user or service, stop and report what you have already observed.

## What to expect

Maintainers will acknowledge a usable report when practical, assess its impact, and coordinate remediation and disclosure with the reporter. Timing depends on severity, reproducibility, affected releases, and the work required for a safe fix, so a fixed response or release deadline is not guaranteed.

For ordinary product problems and feature requests, use the [help center support guide](https://github.com/Sapphire-Learning-Hub/AnonResume/blob/main/src/content/docs/support.en-US.mdx) instead of a security report.
